# 故障排查

[返回项目首页](../README.md) · [服务端指南](../server/README.md)

本文对应 Android 0.12.4。先保存诊断再排查，不要把卸载、清除数据或重新初始化服务端作为第一步。
它们会丢失诊断、配对信息，或改变服务端身份。

<a id="diagnostics"></a>
## 闪退，进不了设置

不需要连接电脑，也不需要先打开主页：

1. 长按 WifiShare 桌面图标，选择“诊断 / Diagnostics”。
2. 若桌面未显示快捷操作，在手机应用列表中打开“WifiShare 诊断 / WifiShare Diagnostics”。这是同一 APK 的第二个入口，不是另一个 App。
3. 点击“复制诊断信息”，粘贴报告；或点击“保存为文件”，通过系统文件选择器导出 `WifiShare-diagnostics.txt`。

独立诊断入口从 0.12.2 开始提供。若仍安装旧版，应先取得同一正式签名的新版本覆盖升级，
保留已有记录；参见[升级与签名](#upgrade)，不要为了找入口先卸载。
如果主页能打开，也可以直接在“设置”中复制诊断信息。

提交反馈时附上：

- APK 版本与来源、手机型号、Android / One UI 版本。
- 导出的诊断报告，以及闪退前执行的具体操作。
- 是否刚覆盖升级、添加小组件或切换服务器，以及大致发生时间。

诊断保留旧日志，修复后也不会自动清空。用 `last-crash.txt` 的时间判断是否产生了新崩溃，
不要把旧异常栈误认为刚刚再次闪退。`[No saved record]` 只表示没有可读记录，
不代表没有发生问题；仍可提供报告中的系统进程退出信息。

报告不会自动上传，代码会排除异常消息、Token 和文件内容，但机型、版本和异常栈仍属于诊断数据。
公开反馈前检查内容，不要附上配对链接、服务器私钥或认证 Token。
Java/Kotlin 异常记录无法覆盖全部原生崩溃、ANR、早期启动失败或系统杀进程。

<a id="connection"></a>
## 无法连接或证书错误

按下面顺序检查，不要先重装：

1. 确认手机与电脑在可互访的局域网。电脑接网线也可以；访客网络、AP 隔离、VPN 路由可能阻止互访。
2. 检查 App 当前选中的服务器。地址必须是 `https://实际局域网地址:8443`，不能使用 `127.0.0.1` 或 `http://`。
3. 确认服务正在运行，且没有同时启动手动 `serve` 和 systemd 服务。
4. 检查防火墙是否只向可信局域网允许 `8443/tcp`；不需要把端口映射到公网。
5. 最后检查 Token、证书指纹是否对应这台电脑的这份配置。

Linux 上的只读检查命令：

```bash
ip -4 addr
ss -ltn 'sport = :8443'
systemctl --user status wifishare.service
journalctl --user -u wifishare.service -n 100 --no-pager
```

未使用 systemd 时，后两条不适用，查看运行 `serve` 的终端即可。
监听存在只说明端口被占用，不证明手机能连接，也不证明监听者一定是 WifiShare。

证书错误时，核对是否重新初始化过服务端、换过证书或误连到别的电脑。
仅重启不会轮换证书；重新 clone 的源码也不包含旧证书与 Token。
确认服务端身份后再更新手机配置，不要关闭 HTTPS 或指纹校验来绕过错误。
需要新配对信息时按[Token 管理](../server/README.md#tokens)签发；
不要用 `repair --ip` 代替查看配置或签发 Token。

## Token 和传输错误

| 现象 | 检查与处理 |
| --- | --- |
| 重启后不知道 Token 在哪 | 重启不会更换 Token；服务端只保存摘要，不能找回旧明文。丢失时签发新 Token |
| HTTP 401 | 核对 Token 是否填错、过期、被撤销，或缺少对应操作权限；不要在字段里添加 `Bearer ` |
| HTTP 413 | 上传超过服务端单文件上限，按容量指南调整 |
| HTTP 507 | 服务端目录容量或剩余磁盘空间不足，检查已有文件及最低预留空间 |
| HTTP 429 | 请求过于频繁，停止连续点击并稍后重试 |
| `phone` 在本地报超限 | 检查电脑到手机单文件上限及队列容量，不是 App 上传上限 |
| 手机无法保存 | 检查手机可用空间；当前接收目录为 `Downloads/WifiShare/` |

操作步骤分别见[Token 管理](../server/README.md#tokens)和[文件上限](../server/README.md#limits)。
调整容量后需要重启服务；普通 Token 签发和撤销对后续请求即时生效。
首次从旧共享 Token 迁移是例外，需要重启以清除进程中的旧凭据。

## 已排队，但手机收不到

- `phone` 只是把文件加入队列，手机必须主动点击下载图标。
- 确认排队所用的仓库 / 配置与手机当前服务器一致；多份 clone 各有自己的 state。
- 自定义配置必须给 `phone` 显式传入 `--config`，参见[环境说明](../server/README.md#environment)。
- 同一服务器的队列不按设备分箱，文件可能已被另一台有接收权限的手机领取。
- 接收异常中断后，已领取但未确认的文件可能暂时不可领取；默认租约为 300 秒，到期后再次接收。
- 手机已保存但确认回执失败时，重试可能产生重复文件。先检查下载目录，不要假定队列重试等于严格去重。

加入队列不会移动源文件。发送取消也不会撤回已经完整到达对端的文件。
更多目录规则见[文件与保存目录](../server/README.md#files)。

<a id="widget"></a>
## 小组件、通知和主题

| 现象 | 当前行为或检查方式 |
| --- | --- |
| 添加小组件没有弹配置页 | 正常；直接使用 App 当前服务器，未配对时显示未配置 |
| 点小组件服务器区域弹出页面 | 正常；这是服务器选择页，确认切换后 App 与所有小组件同步 |
| 想让两个小组件使用不同服务器 | 当前不支持独立绑定，共用一个当前服务器 |
| 小组件明暗与预期不同 | 在 App 设置检查主题；“跟随系统”采用系统明暗，固定浅色 / 深色应与 App 一致 |
| 独立诊断页不跟随 App 固定主题 | 正常；恢复入口为减少依赖而跟随系统主题，不读取业务设置 |
| 设置中的“复制诊断信息”底色不对 | 0.12.4 已改为 App 主题色；先核对安装版本，仍异常时附截图和两处主题设置 |
| 更新后小组件显示陈旧 | 先在 App 检查设置；必要时仅移除并重新添加小组件，不要清除 App 数据 |
| 看不到传输通知 | 检查 Android 的 WifiShare 通知权限；Android 13 及以上需用户允许 |
| 通知看起来出现了多次 | 进度更新会复用通知；若每次都响铃、浮窗或重复出现多个结果，记录触发操作与版本 |

三星设备后台传输异常时，也可检查系统对 WifiShare 的电池与后台运行限制。
这只是排查方向，不代表所有闪退都由系统限制引起。无法定位时优先提供诊断，
不要反复重装以掩盖问题。

<a id="upgrade"></a>
## 升级与签名

正式版 0.12.0 至 0.12.4 使用同一发布证书，可直接覆盖升级，保留配对和诊断。
“release 构建”只表示非调试变体，不保证与已安装版本使用相同的密钥。

安装失败时先检查：

1. APK 来源、文件是否完整、版本是否比当前安装版本更新。
2. 是否混用了正式版、Debug 版或自行签名的版本。
3. 是否出现明确的签名不一致、降级或安装策略限制提示。

0.12.0 以前的旧证书版本不能直接覆盖为当前正式签名。
确实必须卸载时，先导出能取得的诊断，记录服务器信息，并确认能重新获得配对凭据；
再卸载和安装。卸载 / 清除数据会删除 App 内配对与诊断，系统备份不会恢复这些数据。
仅更新 Android 不要求重建服务端或更换 Token。

当前 APK 的获取状态见[安装包说明](../README.md#download)。
不要把历史包改名为新版本，也不要为绕过安装失败重新生成服务端证书。
